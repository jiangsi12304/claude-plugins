# model-compare

一个 Claude Code 命令行插件：提示框旁边有一颗**绿色小圆点**，点一下就把同一个提示词同时发给网关上的两个模型，在左右两栏里并排显示各自的回答、耗时和 token 数。

面板有两种模式：

- **Ask**（默认）：走 `$.model.complete`，两次独立、无工具、无历史的补全调用并发发出，所以两栏可以在同一屏里对照；不改动当前会话的模型，也不写进对话记录。
- **Task**：走 `$.agent.register` + `$.agent.spawn`，每个模型各注册成一个代理类型、起一个真正的子代理（带完整工具循环），各自在**自己选的文件夹**里执行同一段提示词。两个文件夹必须不同，而且**每次执行前都要重新选**——上一次选的两个文件夹用一次就清空，防止两次运行落在同一处、互相踩到对方的改动。

## 功能

- **绿色小圆点**：画在提示框那一行（`PromptHint`）的最前面，颜色跟随主题的 `success`。点一下即打开比较面板、填入提示词并开始比较。
- **左右并排**：宽屏时两栏并排，窄于 64 列（或移动端）时自动上下堆叠。
- **每栏一个边框**：运行中为中性色（暗），答完为绿色，没答出为红色；一眼看出哪一栏还在等、哪一栏失败了。
- **秒数实时走**：正在跑的栏显示 `running 3.4s`，每 250ms 更新一次（引擎的 `$.clock`，不是本地时间），超过一分钟显示 `1m 04s`；跑完固定为最终耗时。数字用等宽数字（`tabular`），跳动时不抖。
- **同一提示词**：打开时优先取提示框里正在输入的内容，其次是本会话最后一条用户消息；两栏收到的是完全相同的文本。面板里也有一个 prompt 输入框，面板持有键盘时可以直接在那里改，改完按 `Compare` 就用新的。
- **每栏显示**：模型 id、耗时、输入 / 输出 token 数、**生成速度**（tok/s，输出 token ÷ 耗时）、回答正文（按 Markdown 渲染，和助手回复一样，代码块与列表都认）；失败的栏写明原因（API 错误的状态码与类型、空回答、被取消）。
- **盲测**：点 `🙈 Blind` 把两栏改成 Column A / Column B，先只看回答质量，判断完再点 `👁 Reveal` 揭晓哪个是谁——像 LMArena 那样避免品牌偏好影响判断。
- **评分与胜者**：两栏都答完后，每栏下方有 `1☆`–`5☆` 可打分；两栏都打完面板会宣布胜者（或平局）。点 `Keep to history` 把这一局记进历史（最近 50 局，存 `$.store`，跨会话保留），状态行还会报这两个模型的**历史交锋比分**（如 `2–1 cn:model-a leads`）。
- **模型当裁判**：点 `⚖ Judge`，插件把两份回答**匿名化**（标成 A/B，且顺序随机对调）交给一个模型当裁判，按正确性、完整性、清晰度打 1–10 分，回复胜者和一句理由。面板显示 `⚖ Judge: 9/10 vs 7/10 — <胜者> wins` 加理由，并自动把 10 分制换算成 5★ 填进评分。你不用自己评分——裁判代劳；手动打分仍然可用。
- **单栏重试**：Ask 模式下，答完的栏下面有 `↻ Retry`，只重问这一栏，另一栏已经拿到的回答不用再花一次。
- **键盘操作**：面板打开时持有焦点，`r` 运行 / `s` 对调 / `c` 取消（进行中）/ `Esc` 关闭。
- **进度也写在状态行**：面板收起或切走时，底部状态行仍有 `compare · asking …` / `compare · 2/2 answered · 1.2s`；一次运行结束时弹一条 toast。
- **两个模型可改**：面板顶部两栏各是一个下拉选择器（`Select`），选项就是网关 `GET /v1/models` 返回的模型列表，方向键选、回车定；列表里没有的 id 点右边的 `✎` 切成输入框手打。`⇄ Swap` 对调左右；`Next model ›` 在列表里循环右栏的模型。
- **复制**：每栏回答下方有 `Copy`，复制该模型完整的回答（屏幕只画前 2000 字符）。
- **两种模式**：`Ask` 两栏各答一次；`Task` 两栏各起一个子代理真去干活，回答经 `turn.complete` 按 `agentId` 收回对应那一栏。
- **每栏一个文件夹**：Task 模式下每栏有一个文件夹下拉（列出会话目录下的子文件夹），点 `✎` 可手打路径；文件夹必须是真实存在的目录，两栏必须不同——选成同一个时，Run 之前面板就会提示。
- **文件夹用一次就清空**：一次 Task 运行成功启动后，两个文件夹选择立即清空，下一次必须重新选。没选就按 `Run tasks`，面板只会提示 `Pick a folder for each column`，不会启动任何代理。
- **取消**：进行中会出现 `Cancel`。Ask 模式立刻中止这一对调用；Task 模式给两个子代理各发一条停止消息，并丢弃它们之后才到的回答（引擎没有直接杀掉子代理的接口）。
- **记住右栏**：最近一次用的右栏模型存进插件存储，跨会话恢复。

## 安装

开发时直接从文件夹加载（仅该会话）：

```sh
claude --plugin-dir path/to/model-compare
```

或让每个会话都加载：在 `~/.claude/settings.json` 的 `env` 里加

```json
{ "CLAUDE_CODE_PLUGIN_DIRS": "D:\\test\\fff\\model-compare" }
```

安装为正式插件则把本文件夹作为 marketplace 仓库，然后：

```sh
/plugin install model-compare --marketplace <owner>/<repo>
```

## 用法

- 点提示框旁边的 **绿色小圆点**：打开面板、填入提示词、同时问两个模型。
- 或敲 `/compare [提示词]`：同上，带参数时用参数作提示词。
- 面板里左右两栏的模型从下拉列表里选（网关列出的 id），点 `✎` 可手打列表外的 id；按 `Compare`（或 `r`）用同一个提示词再问一次。
- 某一栏没答出来，点它下面的 `↻ Retry` 只重问那一栏。
- 想让它真的执行任务：点面板上的 **Task** 切换模式，给左、右两栏各选一个**不同**的文件夹，再按 **Run tasks**。两栏会各起一个子代理，在各自文件夹里跑同一段提示词；结束时该栏自动显示它的回答。
- 一次运行结束后文件夹已被清空：**下一次执行前必须重新给两栏各选一个文件夹**。
- `⇄ Swap` 对调两栏；`Next model ›` 换右栏的模型；`Copy` 复制整段回答；`Esc` 关闭。
- 键盘：`r` 运行、`s` 对调、`c` 取消（运行中）、`Esc` 关闭。面板打开时它就持有键盘；点回提示框后按键归提示框。

## 两栏的模型怎么选

- **左栏**：默认是当前会话的模型（`$.session.model()`，去掉 `[1m]` 这类上下文后缀）。可以从下拉列表里改。
- **右栏**：依次尝试配置项 `rightModel`、上次记住的右栏模型、网关列表里第一个与左栏不同的模型。
- 两栏相同时面板会拒绝运行并提示换一个——比较同一个模型没有意义。
- 模型 id 原样交给引擎，所以 `cn:…`、`global:…` 这类网关 id 都能用。

## 配置（`/config` 里的五行）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `showDot` | boolean | `true` | 是否在提示框旁画绿色小圆点 |
| `rightModel` | string | `""` | 右栏默认模型 id；留空则用上次记住的 |
| `paneRows` | number | `24` | 面板内联时请求的高度（行） |
| `maxTokens` | number | `1024` | 单次回答的 token 上限 |
| `timeoutSeconds` | number | `120` | 单次调用的超时（秒），超时记为被取消 |

## 凭据

比较本身用的是会话自己的 API 客户端（`$.model.complete`），不需要插件另配凭据——会话怎么连网关，两次补全就怎么连。

只有右栏的候选模型列表需要读网关的 `GET /v1/models`：依次尝试 `ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_API_KEY`，以 `Authorization: Bearer …` 发送（同时附 `x-api-key`）。请求走宿主的 `$.http.fetch`；令牌只留在进程内，不写入任何文件。网关不答也不影响比较——两栏的模型 id 都可以手打。

## 说明与限制

- **Ask 模式**的两次调用是独立的单轮补全，**不带工具、不带会话历史、不带系统提示词**；回答只取决于提示词本身，只是把两个模型对同一句话的回答并排放在一起。
- **Task 模式**才是真正的执行：每个模型一个子代理，有完整工具循环，在各自的文件夹里读写文件、跑命令。两栏的改动互不可见——这正是要求两个文件夹不同的原因。子代理的回答以 `turn.complete` 事件返回，插件按 `agentId` 认领到对应那一栏；如果某个代理起不来（被拒绝、拿不到 id），该栏立刻写明原因。
- **Task 模式的模型怎么落到网关上**：Agent 工具的 `model` 参数只认 `sonnet` / `opus` / `haiku` / `fable` 四个别名，直接把 `global:…` 这类网关 id 交给 `$.agent.spawn` 会在代理启动前被拒绝（就是两栏都红着显示 `Invalid option` 的原因）。所以插件改用 `$.agent.register`：每栏的模型各注册成一个同名同模型的代理类型（`<插件名>:task-…`），spawn 时用 `subagentType` 指名那个类型，模型随类型走，网关 id 原样生效。这些类型用 `agent.offer` 从模型自己的代理列表里藏起来，只有面板的 Run 会用。
- **文件夹**：`cwd` 会一并交给 `$.agent.spawn`，但并非每个引擎版本都会把插件的 spawn 搬进那个目录（本机实测代理仍在会话目录里跑）。因此任务的提示词开头也写明「只在这个文件夹里工作，所有路径都用它的绝对路径」——即使 `cwd` 没生效，代理也知道该在哪干活。
- 引擎**没有停止子代理的接口**：`Cancel` 只是给两个代理各发一条停止消息，并在本地丢弃它们之后送来的回答。它们仍可能把已经动手的改动做完。
- 想比较「带完整上下文」的回答可用 `$.model.fork`，但它只能跑会话自己的模型，无法两模型并排。
- 屏幕只画每栏回答的前 2000 字符，完整回答用 `Copy` 取。
- 回答按 Markdown 渲染（和助手回复同一套），所以模型输出里的代码块、列表、标题都会正常显示。
- 秒数来自引擎的 `$.clock`，只在运行中有 tick；运行结束就停，不会在后台空转。
- token 数是引擎返回的 `usage`（输入 / 输出），插件不估算金额——网关的计价插件不知道。
- 面板宽度不足 110 列时会以「提示框上方」的方式显示；更窄时引擎会让它等待，原因写在调试日志里。
- 移动端不画模型选择器、输入框和文件夹选择器（移动端没有 `Input` / `Select`），只显示两栏结果与按钮；要换模型或选文件夹请在终端或桌面端操作。
- 回答、模型 id、网关返回的文本在画之前都会清掉 ANSI 控制序列：绘制引擎会拒绝任何含控制字符的树，不清洗就会整块画不出来。

## 开发

```sh
claude plugin validate .   # 读清单和模块源码，报告会被拒绝的东西
claude plugin test .       # 跑 tests/ 下的 *.test.tsx
```

- `hooks/register.tsx`：全部逻辑（小圆点、面板、Ask 的两次并发调用、Task 的两栏子代理与文件夹校验、取消、复制）。
- `types/index.d.ts`：`$.state` 的值契约（插件声明的每个值都在这里）。
- `tests/compare.test.tsx`：小圆点与打开面板、两栏结果与 token、生成速度、API 错误栏、转义序列回归、关闭小圆点、下拉选模型与 `✎` 手打、移动端、单栏重试、实时秒数（`mock.clock`）、盲测与揭晓、评分与胜者、历史交锋，以及 Task 模式（每栏一个文件夹、每栏自己的模型类型、`turn.complete` 回填、同文件夹拒绝且选时就提示、文件夹不存在拒绝、每次重选文件夹、取消丢弃迟到回答）等用例。
